# Revision Pass 2 — Character & Motif Matrix

## 목적
주요 의인화 인물들이 모두 `똑똑한 해설자` 한 명처럼 수렴하는 것을 막는다. 각 인물은 같은 사건을 보더라도 서로 다른 질문을 해야 한다.

| 인물 | 먼저 보는 것 | 기본 질문 | 말투 | 두려움 | 성장 방향 |
|---|---|---|---|---|---|
| Bitcoin | 검증, 키, 변경권한, 출구 | `누가 결정하지?` | 짧고 건조함 | 임의적 권력, 숨은 문지기 | 코드만 보던 존재 → 인간 합의도 인정 |
| Ethereum | 가능성, 설계, 조합성 | `그럼 이것도 만들 수 있지 않을까?` | 질문 많고 감정적 | 복잡성이 만든 실패 | 발명가 → 도시 운영자 → 정산층의 시장 |
| Stablecoins | 상환, 준비금, 유동성 | `1달러로 돌아갈 수 있나?` | 회계적, 실무적 | 이름만 믿는 안전성 착각 | 피난처 → 금융 혈액 → 규제 결제 인프라 |
| Credit | 약속, 담보, 레버리지 | `누가 갚지?` | 여유롭고 구조적 | 위험이 숨는 것 | 적대자 → 사라지지 않는 기능 |
| Price | 군중의 기대 | `사람들이 지금 얼마를 걸었지?` | 빠르고 변덕스러움 | 무관심 | 작은 숫자 → 군중의 확성기 → 제도권 번역기 |
| State | 권리, 의무, 강제력 | `누가 책임지지?` | 느리고 절차적 | 책임 공백과 통제 실패 | 단속자 → 분류자 → 협상자 |
| Institutions | 운영위험, 상품성, 위임책임 | `이걸 관리 가능한 상품으로 만들 수 있나?` | 계산적, 실용적 | 예측 불가능한 규칙 | 관찰자 → 상품화 → 인프라 이용자 |
| Exchanges | 유동성, 접근성, 수탁 | `사람들이 가장 쉽게 거래하려면?` | 장사꾼, 실용적 | 뱅크런과 신뢰 상실 | 입구 → 권력 집중 → 반복되는 수탁 문제 |
| Solana | 처리량, 체감 UX | `왜 이렇게 느리지?` | 자신감, 속도감 | 멈춤과 복구 실패 | 도전자 → 장애를 겪은 운영자 |
| Chainlink | 입력 데이터, 연결 | `그 숫자를 어디서 알지?` | 차분하고 정확함 | 단일 병목과 잘못된 입력 | 전령 → 금융 인프라의 관측망 |
| XRP | 연결, 결제경로, 법적 분류 | `실제로 움직일 수 있나?` | 외교적, 실무적 | 장기간의 법적 불확실성 | 속도 중심 → 법의 언어를 아는 실무가 |

## 대사 충돌 방지 규칙
1. Bitcoin과 Ethereum이 연속해서 같은 냉소를 하지 않는다.
2. 국가가 수익·상품성을 설명하면 Institutions로 옮긴다.
3. Institutions가 범죄·권리구제를 설명하면 국가로 옮긴다.
4. Credit이 특정 회사의 사실관계를 확정하는 판사처럼 말하지 않는다.
5. Price가 가치판단을 하면 안 된다. 그는 반응만 한다.
6. Stablecoins가 가족 전체를 단일 발행구조처럼 말하지 않는다.
7. Chainlink는 `진실을 안다`고 말하지 않는다. 관측과 전달을 담당한다.
8. Exchanges는 protocol을 대표하지 않는다. 편리한 입구와 수탁 위험을 대표한다.

## 반복 모티프와 담당 인물

### 열쇠
- 주 담당: Bitcoin, Exchanges, Institutions
- 의미 변화: 개인키 → 수탁권한 → 제도적 위임

### 장부
- 주 담당: Bitcoin, Stablecoins, Credit
- 의미 변화: 검증 가능한 기록 → 준비금/상환 기록 → 보이지 않는 약속의 지도

### 문 / 성문 / 출구
- 주 담당: Exchanges, State, Institutions, Bitcoin
- 의미 변화: 접근성 → 허가 → 상품화 → 떠날 수 있는 권리

### 도시
- 주 담당: Ethereum, Solana
- 의미 변화: 프로그래머블 도시 → 경쟁 도시 → L2 연방

### 정장
- 주 담당: Stablecoins, Institutions, State
- 의미: 제도 편입. 단, 정장은 안전의 보증이 아니라 책임과 규칙의 추가를 뜻한다.

### 지도
- 주 담당: Ethereum, Credit, Chainlink
- Ethereum은 설계를 그린다.
- Credit은 연결된 약속을 그린다.
- Chainlink는 데이터·병목의 연결을 그린다.
