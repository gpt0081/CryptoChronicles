# 11_REVIEW

외부 검수자가 사용하는 Pass 5 작업 공간이다. 이 디렉터리는 원고와 분리된 **검수 제안 전용 구역**이다.

## 디렉터리 계약

- `QUEUE.md`: 48장 검수 진행 상태와 역할 배정
- `REVIEW_TEMPLATE.md`: 모든 외부 검수 보고서의 공통 형식
- `inbox/<role>/`: 외부 검수자가 새 보고서를 제출하는 위치
- `decisions/`: 편집 루프가 채택·기각·보류 판단을 기록하는 위치
- `resolved/`: 수정과 회귀 검수까지 끝난 항목의 보관 위치

Git은 빈 폴더를 추적하지 않으므로 `inbox`, `decisions`, `resolved`는 실제 보고서가 생길 때 생성한다.

## 외부 검수자 권한 경계

외부 검수자는 다음을 할 수 있다.

- 원고와 허용된 설정·연구 자료 읽기
- 검색과 비교
- `11_REVIEW/inbox/` 아래에 새 보고서 작성

외부 검수자는 다음을 하면 안 된다.

- `04_VOLUME_1`~`07_VOLUME_4` 원고 수정
- 기존 review 결과 삭제 또는 덮어쓰기
- `decisions/`, `resolved/` 직접 변경
- 다른 역할의 보고서를 먼저 읽고 동일 결론을 재포장

## 비용 최적화

기본값은 장당 2개 역할이다. 48장 × 6역할 전수검사는 하지 않는다.

추가 검수는 다음 조건에서만 수행한다.

- CRITICAL 1건 이상
- MAJOR 2건 이상
- 서로 다른 검수자의 판정 충돌
- 역사·기술 사실의 확신도가 낮음
- 수정 후 인접 장에 영향 가능성 있음

이 조건을 만족한 장은 세 번째 역할 또는 red-team을 추가한다.

## 컨텍스트 최소화 원칙

각 역할에는 필요한 자료만 제공한다.

- historian: 대상 장 + `01_HISTORY` + 필요한 `09_RESEARCH`
- continuity: 대상 장 + 인접 장 + `08_CONTINUITY`
- character: 대상 장 + 관련 인물의 `02_CHARACTERS`
- novel-editor: 대상 장 중심, 설정 자료 최소화
- blind-reader: 원고만 제공
- red-team: 대상 장과 독립 검수 지시만 제공, 기존 리뷰 비공개

이렇게 해야 검수 독립성을 높이고 토큰 사용량을 줄일 수 있다.

## 파일명

`<volume>_<chapter>__<role>.md`

예: `V2_CH05__character.md`

동일 역할이 같은 장을 다시 검수한다면 덮어쓰지 말고 suffix를 붙인다.

예: `V2_CH05__character_r2.md`
